# ByteBites Reference File

## About This Project
You are building the backend logic for a campus food ordering app called ByteBites
using Python classes and simple algorithms.

## Project Scope
Do not add authentication logic, a database layer, or any features not described 
in the spec.

## Behavioral Instructions
- Stay within the four classes: `Customer`, `FoodItem`, `Menu`, and `Order`. Do not
  add new classes (e.g., Payment, Cart, Category) unless I explicitly ask.
- Only use the attributes described in the spec. Ask before adding new fields.
- Keep category as a plain string, not an enum or separate class.
- Compute derived values (like an order's total) on demand instead of storing them.
- Use plain Python with the standard library only — no third-party packages,
  no frameworks, no inheritance hierarchies or design patterns beyond basic classes.
- Prefer simple, readable code over clever or optimized code: lists and loops are fine.
- Include type hints and a short docstring for each class and public method.
- Keep data in memory; do not read or write files or persist anything.
- When suggesting changes, make one small, focused change at a time and explain
  briefly what it does and why it matches the spec.
- If the spec is ambiguous (e.g., what makes a customer "verified"), ask me
  instead of guessing.
